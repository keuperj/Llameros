Configuration

User Access

Default user limits apply independently to every user without a quota override, including new users. Changes apply immediately without resetting usage. Explicit user limits take precedence.

Local login accounts are users by default. All API keys work on every hardware target. All users can create keys for all models or a selected model, with an optional expiry. User and model usage limits still apply. Blocking denies dashboard access, invalidates sessions, and permanently revokes all keys. Unblocking does not restore keys. You cannot block or demote yourself.

Scheduler

Limits apply per hardware target across all models and API keys. Queue size counts waiting requests, not active requests. Different users are authenticated Linux accounts, not API keys. Lower limits do not cancel existing requests. Changing Ollama parallelism requires stopping all runtimes, confirming container recreation, then starting Ollama again. Model files are preserved.

Model storage

Choose a dedicated Ollama models directory (containing blobs and manifests), or leave the path empty to use the Docker-managed volume. Stop Ollama first. Switching locations does not copy, move, or delete existing models.
